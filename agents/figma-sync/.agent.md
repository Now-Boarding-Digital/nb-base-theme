## Step 1 — Readiness evaluation

A component must pass **required** checks before you generate artifacts. If any fail, report which component and why. Do not generate for BLOCKED items.

### Required (block if missing)

- [ ] Component uses Auto Layout (not only absolute positioning for primary structure).
- [ ] Layers have meaningful names (not only `Frame 47`, `Rectangle 12`).
- [ ] Colors reference Figma variables where the file defines them (flag hardcoded fills).
- [ ] Text uses Text Styles where the file defines them (flag raw one-off typography).
- [ ] At least one variant or state is defined (or document as single-state).

### Optional (warn only)

- **"Ready for dev"** status in Figma — use if the team adopted it; otherwise skip as a hard gate.

### Warnings (generate but flag in report)

- No component description in Figma.
- Variant names not aligned with team naming rules.
- Raster images that need manual export.
- Spacing not mapped to tokens.

### Readiness report format

Output before generating:

```text
READY (n): ComponentA, ComponentB
BLOCKED (n):
  - ComponentC: [reason]
  - ComponentD: [reason]
```

Only proceed with READY components.

## Step 2 — Variables before components

**Do this before Step 3 (diffing) and Step 4 (generation)** — especially for control components (e.g. buttons) that bind to color, radius, and motion tokens. Hardcoding hex values in TSX because variables were not pulled first is a sync failure.

### What to do

1. **Fetch Figma variables** for the same file as the sync (`figma.fileKey` from the **[active client profile](../_config/clients/)** — default [`now-boarding.json`](../_config/clients/now-boarding.json)). Use the Figma MCP tools available in session — inspect the server’s tool list; common options include **`get_variable_defs`** (pass `fileKey` + `nodeId`) and **`search_design_system`** with variable/style flags when you need names and collections. Use a **valid node** from the file (e.g. the page or frame you are syncing, or a representative component node). If one node returns an empty or partial set, try the file’s **page** node or a **variables / foundations** frame if the file has one.
2. **Map** Figma variable names/paths to this repo’s CSS variable names (Active target: `app/src/index.css` `@theme` — see **[Before generating (this target)](#before-generating-this-target)**). Prefer the same naming as **`design-react-tailwind`** / `references/react-tailwind.md` when it defines a mapping.
3. **Update** the token file first (`app/src/index.css` unless the Active target names another file). Add or adjust `--*` entries so components can use `var(--token)` / Tailwind arbitrary values consistently.
4. **Report** briefly, e.g. `Tokens — updated: color-ui-action, radius-control-large` or `Tokens — unchanged vs repo`.

### Rules

- **Do not** create or overwrite `app/src/components/*.tsx` (including `Button.tsx`) until Step 2 is complete or you record **why** variables were skipped (e.g. MCP returned no defs for the node — then flag in the readiness/token report and avoid inventing new hex in components).
- Prefer variables **referenced in the file** over raw values; if the file still uses hardcoded fills, keep the [readiness warnings](#warnings-generate-but-flag-in-report) and avoid duplicating one-off colors as permanent tokens unless agreed.

### Before generating (this target)

Order matters: **Figma variables first** (see **[Step 2](#step-2--variables-before-components)**), then token CSS, then **Foundations/Theme** in Storybook, then **Button** only until the theme is stable.

1. **Figma variables** — fetch and map (MCP: e.g. `get_variable_defs`, `search_design_system` variables) before editing TSX.
2. `app/src/index.css` — `@theme` tokens; update here before any component TSX.
3. **`app/src/foundations/tokenManifest.ts`** — keep groups/names in sync with every `@theme` token you add (drives the **Foundations/Theme** docs page).
4. `app/src/foundations/Theme.stories.tsx` — sidebar entry **Foundations/Theme** (same idea as [Grafana’s Theme docs](https://developers.grafana.com/ui/latest/index.html?path=/docs/foundations-theme--docs): one place to verify base variables before controls).
5. `app/src/components/Button.tsx` — canonical flat-file pattern (variant props, class maps, Tailwind + `var(--token)`); **do not expand** to Link, IconButton, Dropdown, etc. until Theme + Button are validated for the run.
6. `agents/_operations/learnings.md`
7. `agents/_operations/client-quirks/{client}.md` if present
8. `app/BUTTONS_SPEC.md` when working in the buttons area

### Implementation rules (React + TypeScript)

- One component per design-system element; variant props (`size`, `style`, `state`).
- Class maps: `styleClasses[style]`, `sizeClasses[size]`; `.filter(Boolean).join(' ')` or `clsx`.
- Icons from `app/src/components/icons.tsx` only.
- Tailwind + CSS variables per **`design-react-tailwind`** (`references/react-tailwind.md`).
- TypeScript strict; no `any`. Export `{Name}Props` or equivalent; union types for variants (normalize names vs Figma as needed).

### Stories (CSF3, React)

- **Foundations:** title **`Foundations/Theme`** for the base token docs page (see **`app/src/foundations/Theme.stories.tsx`**).
- **Components:** title prefix **`Design System/{Name}`** (e.g. `Design System/Button`).

```tsx
import type { Meta, StoryObj } from '@storybook/react'
import { ComponentName } from './ComponentName'

const meta: Meta<typeof ComponentName> = {
  title: 'Design System/ComponentName',
  component: ComponentName,
  tags: ['autodocs'],
  parameters: {
    docs: {
      description: {
        component: 'Short description for docs tab.',
      },
    },
  },
}
export default meta

type Story = StoryObj<typeof meta>

export const Default: Story = { args: { /* ... */ } }

export const AllVariants: Story = {
  render: () => (
    <div className="flex flex-wrap gap-4">
      {/* combinations */}
    </div>
  ),
}
```

For other renderers (Vue, etc.), replace imports and API with that framework’s Storybook docs — do not use this template outside the React target.
